# «Общество тайн» — Telegram-бот закрытого клуба

Готовый бот для подписки **790 ₽/мес** с рекуррентными платежами через **Prodamus**, закрытым каналом, чатом обсуждений, авто-киком и админ-панелью для Марины.

Реализован весь сценарий из ТЗ: 6 сообщений, одноразовые ссылки, синхронная выдача и отзыв доступа, напоминание на 27-й день, исключение на 31-й, уведомления админу, ручная выдача доступа, промокоды и **отмена подписки самим участником** (в режиме автосписаний — через Prodamus Rest API, в бесплатном режиме — прекращает напоминания о продлении).

> 📖 Впервые берёте в руки бота? Начните с файла **[КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md)** — там по шагам, простым языком, без терминов.

| 4 | Напоминание за 3 дня до списания | Планировщик каждые 10 минут, отметка «уже напомнили» (без спама) | `bot/services/tasks.py` |

| — | Уведомления Марине об оплате | «🎉 Новая оплата…» / «🔁 Продление…» в личку каждому из `ADMIN_IDS` | `bot/services/access.py` |
| — | Админ-панель: ручная выдача доступа | кнопка «🎁 Выдать доступ» (ID, @username или пересылка сообщения), срок в днях | `bot/handlers/admin.py` |
| — | Промокоды на скидку | создание/отключение в панели, ввод пользователем, скидка уходит в `discount_value` Prodamus | `bot/handlers/admin.py`, `bot/db.py` |
| — | **Отмена подписки** | кнопка «Отменить подписку» → подтверждение → `POST /rest/setActivity/` в Prodamus + отметка в БД, доступ живёт до конца периода, напоминания прекращаются, Марине уведомление. **В бесплатном режиме** (без `PRODAMUS_SUBSCRIPTION_ID`) кнопка тоже работает: она отключает напоминания, в Prodamus не ходит | `bot/services/subscriptions.py`, `bot/handlers/user.py` |

Дополнительно от себя (не ломает ТЗ):

* `/status` — участник видит дату окончания доступа, как устроено продление и отменена ли подписка;
* кнопка «Получить новые ссылки» — если одноразовая ссылка истекла (24 часа), не нужно писать Марине;
* защита от двойной выдачи: повторный вебхук по тому же заказу игнорируется;
* проверка подписи вебхука (включая отказ демо-платежам Prodamus);
* при старте бот сам проверяет, что он админ в канале и чате, и пишет об этом Марине;
* журнал всех платежей + статистика (выручка за месяц и всего, активные подписки, продления в ближайшие 3 дня).

## 4. Заполнение `.env`

| Переменная | Что это | Пример |
|---|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) | `123456789:AA…` |
| `ADMIN_IDS` | Telegram ID Марины (можно несколько через запятую) | `123456789` |
| `CHANNEL_ID` | закрытый канал: `@username` или `-100…` | `@obschestvo_tayn` |
| `CHAT_ID` | чат обсуждений | `-1001234567890` |
| `PRICE` | цена подписки | `790` |
| `SUBSCRIPTION_DAYS` | срок доступа после оплаты | `30` |
| `GRACE_DAYS` | отсрочка перед киком | `1` |
| `REMINDER_DAYS_BEFORE` | за сколько дней напоминать | `3` |
| `INVITE_LINK_TTL_HOURS` | срок жизни одноразовой ссылки | `24` |
| `PRODAMUS_FORM_URL` | адрес платёжной формы (из адресной строки) | `https://demo.payform.ru/` |
| `PRODAMUS_SECRET` | секретный ключ платёжной страницы | `2y2aw4ok…` |
| `PRODAMUS_SUBSCRIPTION_ID` | **ID подписного товара** (включает автосписания) | `618988` |
| `PRODAMUS_SYS` | код интеграции SYS (запросить в поддержке Prodamus; можно пусто) | |
| `PRODAMUS_SEND_TG_USER_ID` | передавать в Prodamus `tg_user_id` (нужно для отмены подписки по API) | `true` |
| `WEBHOOK_PORT`, `WEBHOOK_PATH` | куда Prodamus шлёт уведомления | `8080`, `/prodamus/webhook` |
| `PUBLIC_BASE_URL` | публичный HTTPS-адрес сервиса | `https://club.example.com` |
| `SUPPORT_CONTACT` | контакт в `/help` и в ошибках | `@marina` |
| `DB_PATH` | файл базы | `data/club.db` |
| `TZ` | часовой пояс для дат в сообщениях | `Europe/Moscow` |

Если `PRODAMUS_SUBSCRIPTION_ID` пустой — бот работает в режиме **ручного продления** (каждый месяц человек платит сам), и при старте предупредит об этом. Рекуррент — это именно ID подписного товара.

### Бесплатный режим: ручное продление вместо робота автосписаний

Робот рекуррентных платежей Prodamus — платный (1000 ₽ при подключении, 2000 ₽ в
процессе и +1% к тарифу по картам). Поэтому бот умеет работать **без него, за 0 ₽**:

| Этап | Что делает бот |
|---|---|
| За 3 дня до конца | «Кажется, пришло время продлить…» + кнопка **прямо на страницу оплаты** |
| В день окончания | «Сегодня последний день Вашего пропуска…» + та же кнопка |
| На следующий день | «Пропуск вчера закончился…» + срок отсрочки и кнопка оплаты |
| Отсрочка (`GRACE_DAYS=3`) | доступ ещё работает — человек может спокойно оплатить |
| После отсрочки | исключение из канала и чата + «Вернуться в клуб» |
| После оплаты | срок **добавляется** к остатку, напоминания сбрасываются |

Каждое напоминание приходит один раз за период оплаты, кнопка ведёт сразу на форму
оплаты с готовым заказом (один клик, не два). Для ручного режима в `.env` стоит
`GRACE_DAYS=3`; если позже включите автосписания — поставьте `1`.

## 5. Настройка Telegram

1. **Создать бота**: @BotFather → `/newbot` → скопировать токен в `BOT_TOKEN`.
2. **Канал**: создать закрытый канал, добавить бота **администратором** с правами:
   * «Приглашать пользователей по ссылке» (обязательно — бот создаёт одноразовые ссылки);
   * «Блокировать участников» (обязательно — авто-кик);
   * «Удалять сообщения» — по желанию.
3. **Чат обсуждений**: привязать к каналу или создать отдельный закрытый чат, добавить бота админом с теми же правами.
4. **ID чатов**: напишите `/chatid` в канале и в чате — бот (если он уже админ) покажет ID. Альтернатива: переслать сообщение из чата боту @userinfobot.
5. **Свой Telegram ID** (для `ADMIN_IDS`): @userinfobot.
6. Перед запуском бот должен быть админом — иначе ссылки не создадутся.

Важно: бот не может писать человеку первым, пока тот не нажал `/start`. Поэтому «Выдать доступ» по ID без `/start` со стороны пользователя не доставится — панель честно об этом сообщит.

## 6. Настройка Prodamus

1. **Включить подписки**: Prodamus → «Подписки» → создать подписной товар «Общество тайн», 790 ₽, интервал 30 дней (или 1 месяц), нужное число попыток списания. Скопировать **ID товара** → `PRODAMUS_SUBSCRIPTION_ID`.
2. **Секретный ключ**: Prodamus → Настройки платёжной страницы → скопировать секретный ключ → `PRODAMUS_SECRET`.
3. **URL для уведомлений** (два поля — оба обязательны):
   * «URL-адреса для уведомлений» (первый платёж) → `https://ваш-домен/prodamus/webhook`;
   * «URL-адреса для уведомлений об оплате по подписке» (продления, неудачные списания, предстоящее продление, завершение) → тот же адрес.
4. **Проверить** кнопкой «Тестировать запрос» в кабинете Prodamus — в ответ должно прийти `success`.
5. **Боевой режим**: демо-подписи (`…demo`) бот намеренно отвергает, чтобы тестовые платежи не выдавали доступ.

Что бот присылает в Prodamus в ссылке: `order_id` вида `tg123456789-ab12cd34ef56`, `customer_extra=tg:123456789`, `tg_user_id`, `subscription`, при промокоде — `discount_value`, и подпись `signature`.

**Про подпись (проверено на живой форме).** Prodamus принимает подпись только в том случае, если кириллица в JSON остаётся в UTF-8; если экранировать её как `\uXXXX` (поведение PHP `json_encode` по умолчанию), форма молча отбрасывает параметры ссылки. Вариант, который работает: `ensure_ascii=False` + экранирование «/», HMAC-SHA256. Проверить на своей форме в любой момент: `python scripts/check_prodamus.py` (скрипт показывает HTTP-ответ на тестовую ссылку и перебирает альтернативные форматы, если основной отклонён).

Как бот понимает, кому выдать доступ: сначала по `order_id` (он есть в базе), затем по `customer_extra`, затем по телефону/почте из прошлых платежей. Это тройная страховка на случай, если Prodamus в продлении не передаст `order_id`.

## 8. Деплой

Нужен любой сервер с публичным доменом (для HTTPS-вебхука) — например, VPS за 200–400 ₽/мес.

### Вариант 0 (самый простой): установщик одной командой

На чистом сервере Ubuntu/Debian, из папки с проектом:

```bash
cd /opt/obshchestvo-tayn && bash deploy/install.sh
```

Скрипт поставит Docker, спросит токен/ID/ключи, создаст `.env`, поднимет HTTPS
(если своего домена нет — предложит бесплатный `IP.nip.io`) и в конце покажет
адрес вебхука для Prodamus. Подробнее — в [КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md).

### Вариант А: Docker Compose + Caddy вручную

```bash
# 1. на сервере: домен club.example.com уже указывает A-записью на этот сервер
git clone <репозиторий> /opt/obshchestvo-tayn && cd /opt/obshchestvo-tayn
cp .env.example .env && nano .env        # заполнить, PUBLIC_BASE_URL=https://club.example.com
sed -i 's/club.example.com/ваш-домен/' deploy/Caddyfile
docker compose up -d --build
docker compose logs -f bot
```

Caddy сам получит сертификат Let's Encrypt и проксирует 443 → bot:8080. В Prodamus вписываете `https://ваш-домен/prodamus/webhook`.

### Вариант Б: systemd + nginx/Caddy на хосте

```bash
sudo adduser --system --group club
sudo mkdir -p /opt/obshchestvo-tayn && sudo chown club:club /opt/obshchestvo-tayn
# скопировать проект, затем:
sudo -u club python3 -m venv /opt/obshchestvo-tayn/.venv
sudo -u club /opt/obshchestvo-tayn/.venv/bin/pip install -r requirements.txt
sudo cp deploy/obshchestvo-tayn.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now obshchestvo-tayn
sudo journalctl -u obshchestvo-tayn -f
```

Сверху — reverse-proxy с HTTPS (Caddy: `reverse_proxy 127.0.0.1:8080`).

Бэкапы: вся база — один файл `data/club.db`, достаточно ежедневного `cp` в бэкап-папку (например, cron + `sqlite3 data/club.db ".backup"`).

## 9. Админ-панель (`/admin`)

| Кнопка | Что делает |
|---|---|
| 📊 Статистика | участники, активные подписки, продления в ближайшие 3 дня, выручка за месяц и всего |
| 🎁 Выдать доступ | принять ID / @username / пересланное сообщение → срок в днях (0 = 30) → человек получает поздравление со ссылками |
| 🚫 Забрать доступ | исключает из канала и чата, закрывает доступ (без прощального текста) |
| 🔁 Отменить автосписание | отключает подписку конкретному человеку от лица администратора (такую отмену можно вернуть в кабинете Prodamus) |
| 🏷 Промокоды | список, создание (код → % скидки → лимит применений → срок в днях), отключение |
| 👤 Найти участника | карточка: статус, доступ до, последняя оплата, телефон, источник доступа |
| `/chatid` | ID текущего чата — для настройки `.env` |
| `/stats` | статистика одной командой |

Промокод применяется пользователем на шаге оплаты: кнопка «У меня есть промокод» → ввод кода → пересчёт цены (скидка уходит в Prodamus как `discount_value`). Один промокод = одна оплата (если не задан иной лимит), после оплаты счётчик увеличивается.

## 10. Как работают таймеры

* **Оплата** → `paid_until = сейчас + 30 дней`, статус `active`, ссылки выданы.
* **Продление** (вебхук Prodamus) → `paid_until = max(текущая дата окончания, сейчас) + 30 дней` — дни не «сгорают», если человек оплатил раньше.
* **День 27** (за 3 дня до окончания) → напоминание из ТЗ; в ручном режиме дальше идут ещё два: в день окончания и на следующий день. Каждое — один раз за период (поле `reminder_stage`).
* В режиме автосписаний (с ID подписного товара) остаётся одно напоминание из ТЗ — за 3 дня.
* **День 31** (30 дней + 1 день отсрочки) → исключение из канала и чата + прощальное сообщение с кнопкой «Вернуться в клуб».
* **Отмена подписки участником** → автосписание выключается, `auto_renew = 0`: напоминания больше не приходят, а исключение происходит **ровно в дату окончания** (без дня отсрочки — платёж ведь не ждём). Доступ всё это время сохраняется.
* Исключение делается через `banChatMember` + сразу `unbanChatMember` — человек реально выходит из чата, но может вернуться по новой ссылке после оплаты (без этого Telegram не пускает обратно).

Проверка идёт каждые 10 минут, поэтому всё срабатывает в пределах десяти минут от расчётного времени. Если сервер лежал — после старта планировщик догоняет пропущенное в первый же тик.

## 11. Что менять без программиста

* **Тексты** — `bot/texts.py`. Все 6 сообщений из ТЗ лежат там дословно, с плейсхолдерами `{price}`, `{date}`, `{days}`. Разметка — HTML (`<b>`, `<i>`, `<code>`).
* **Цена** — `PRICE` в `.env` (и сумма подписного товара в Prodamus).
* **Сроки** — `SUBSCRIPTION_DAYS`, `GRACE_DAYS`, `REMINDER_DAYS_BEFORE`.
* **Кнопки** — `bot/keyboards.py`.

После правки текстов достаточно перезапустить бота (`docker compose restart bot` или `systemctl restart obshchestvo-tayn`).

## 12. О чём стоит знать

1. **Одноразовые ссылки**: `member_limit=1` означает «один вход». Если человек вышел из канала, ссылка уже не сработает — нужна новая (кнопка «Получить новые ссылки» в `/status`).
2. **Отмена подписки**: кнопка «Отменить подписку» есть у любого действующего участника. В бесплатном режиме (ручное продление) она ничего не отправляет в Prodamus — просто прекращает напоминания, доступ закрывается ровно в дату окончания; тексты при этом другие: «Не продлевать подписку?» → «Хорошо, продлевать не будем».
   В режиме автосписаний кнопка «Отменить подписку» в `/status` вызывает `POST /rest/setActivity/` с `active_user=0` — это отписка «от лица пользователя», как если бы он сделал её сам в Prodamus. По правилам Prodamus такую отмену нельзя вернуть через API: чтобы вернуться, человек оформляет подписку заново (бот это поддерживает, доступ просто продлится). Отмена из админки идёт как `active_manager=0` — такую можно включить обратно в кабинете Prodamus.
   Если Prodamus не узнал клиента (нет `tg_user_id`/телефона) — отмена всё равно фиксируется в базе, а Марине приходит уведомление с просьбой выключить автосписание вручную; после этого авто-кик и отсутствие напоминаний работают по расписанию.
3. **Вебхук должен быть на HTTPS** с валидным сертификатом, иначе Prodamus не доставит уведомления (локально можно тестировать по HTTP через `scripts/simulate_payment.py`).
4. **Возвраты**: если делаете возврат в Prodamus, доступ автоматически не снимается — используйте «🚫 Забрать доступ».
5. **Один инстанс**: SQLite + long polling рассчитаны на один процесс. Для нескольких серверов нужно перейти на PostgreSQL и вебхук-режим Telegram — скажите, переделаю.
6. **Юридическое**: рекуррент требует согласия пользователя на платежной странице (галочка в Prodamus), а также оферты/политики. Это настраивается в кабинете Prodamus, код тут не участвует.
